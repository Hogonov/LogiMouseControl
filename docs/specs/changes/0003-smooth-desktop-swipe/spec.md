# CH-0003: Плавное переключение рабочих столов жестом

Статус: реализовано
Путь: полный
Дата: 2026-10-12
Документы: [план](plan.md) · [отчёт](report.md) · ADR: [ADR-0002](../../adr/0002-dock-swipe-synthesis.md)

## Проблема

Пользователь сообщает: жесты работают, но не плавно. Нужно зажать кнопку, сдвинуть мышь, и только после отпускания рабочий стол переключается. Чтобы пройти несколько рабочих столов, жест повторяется для каждого. Пользователь хочет переключение как на трекпаде MacBook: рабочий стол следует за движением, без отдельного жеста на каждый стол.

Что видно в коде (коммит `41d49c7`):

1. `AppModel.handle(_:)` копит Raw XY в `GestureAccumulator` и только при отпускании кнопки определяет направление (`GestureAccumulator.direction`, порог 60 единиц).
2. Для «Рабочий стол слева/справа» `ActionExecutor` отправляет symbolic hotkey 79/81 (`SymbolicShortcut`). Это одно дискретное переключение с готовой анимацией; прогресс не зависит от движения мыши.

Трекпад управляет переходом между рабочими столами событиями DockSwipe: начало, изменения с накопленным прогрессом и конец со скоростью. На macOS 27 Dock читает `IOHIDEvent`, вложенный в событие `CGEvent` типа 30, а не приватные поля `CGEvent` (Mac Mouse Fix, `TouchSimulator.m`, ревизия `f92d2d53a`). У пользователя macOS 27.0.1 (CH-0002).

## Цель

Пока кнопка жестов удерживается, горизонтальное движение мыши непрерывно ведёт системный переход между рабочими столами, как свайп по трекпаду. Длинное движение проходит несколько рабочих столов без отпускания кнопки.

## Не входит в задачу

- Плавные Mission Control и «Окна приложения» по вертикали: остаются дискретными действиями по отпусканию.
- Плавный режим на macOS 14–26: там остаётся прежнее дискретное поведение. Формат событий этих версий отличается, проверить его на Mac пользователя нельзя.
- Новая настройка чувствительности и изменение `preferences.v1`.
- Определение фактического активного рабочего стола через SkyLight (`SLSManagedDisplayGetCurrentSpace`).
- Повторная отправка конечного события через 0,2 и 0,5 с, как в Mac Mouse Fix. Для macOS 27 её польза не подтверждена (комментарий в `TouchSimulator.m`).

## Текущий сценарий

1. Пользователь нажимает кнопку с действием «Жесты»: `AppModel` создаёт `GestureAccumulator`.
2. Сдвиги Raw XY (`0x1B04 fn1`) копятся; на экране ничего не происходит.
3. При отпускании направление по преобладающей оси выбирает действие из `GestureActions`. Для «влево/вправо» это одно переключение через symbolic hotkey 79/81.
4. Для следующего рабочего стола жест повторяется.

## Ожидаемый сценарий

1. Пользователь нажимает кнопку с действием «Жесты». У этой кнопки «влево» и «вправо» назначены «Рабочий стол слева» и «Рабочий стол справа» (в любом порядке). macOS 27 или новее, Универсальный доступ разрешён.
2. Пока сдвиг меньше порога 60 единиц, ничего не происходит. Если первым порог проходит горизонтальный сдвиг, начинается свайп рабочих столов: рабочий стол сдвигается вслед за мышью.
3. Один рабочий стол соответствует 800 единицам Raw XY при 1000 DPI; при другом DPI расстояние пересчитывается пропорционально.
4. Когда накопленный прогресс доходит до целого рабочего стола, текущий сегмент завершается и сразу начинается следующий с остатком. Движение продолжает листать рабочие столы.
5. При отпускании свайп завершается со скоростью последних сдвигов. macOS доводит переход до соседнего стола или возвращает его, как после свайпа трекпадом. Быстрый рывок назад перед отпусканием отменяет переход.
6. Если первым порог прошёл вертикальный сдвиг или горизонтальные направления назначены не рабочим столам, всё работает как прежде: действие по отпусканию.

## Затронутые компоненты и контракты

- Компоненты: `MouseCore` (новые `SpaceSwipe`, `SwipeStep`, `GestureSession`, `GestureActions.desktopSwipeSign`; у `GestureAccumulator` публичное чтение `x`, `y`), новый `DockSwipe` в приложении, `AppModel.handle(_:)`, `configure()`, `onDisconnected`, `shutdown`, `MainView` (подсказка).
- Контракты: формат `preferences.v1` не меняется; команды HID++ и захват не меняются; новые синтезированные события `CGEvent` типа 30 с вложенным `IOHIDEvent` DockSwipe в `.cgSessionEventTap`.
- Инварианты: INV-1/INV-2 — проверки только чистой логики, агент не отправляет события; INV-3 — сдвиги не сохраняются; INV-4 — без сети и зависимостей; INV-8 — `MouseCore` только `Foundation`, приложение работает на macOS 14; INV-9 — подсказка по доступности; INV-16 дополняется завершением свайпа (ADR-0002).
- Анализ влияния: поток 4.2 (Raw XY теперь даёт шаги свайпа во время удержания); владение состоянием 5.1 (`DockSwipe` на main); жизненный цикл 5.2; ранний выход `configure()` больше не сбрасывает `held` и `gestureState`, если захват не меняется.

## Совместимость, миграция и восстановление

- Сохранённые настройки: не меняются; плавный режим выводится из существующих назначений.
- Аппаратное состояние: не меняется. Если процесс аварийно завершится во время свайпа, Dock не получит конечного события; помощник восстанавливает только HID (U-13).
- Откат: назначить «влево/вправо» другие действия либо вернуть предыдущую версию; на macOS ниже 27 режим не включается.
