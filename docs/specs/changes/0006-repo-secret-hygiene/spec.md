# CH-0006: Защита репозитория от случайной публикации конфиденциальных данных

Статус: реализовано
Путь: краткий
Дата: 2026-10-13

## Проблема и ожидаемое поведение

Сейчас: `docs/specs/knowledge-graph.json`, поле `context.workingDirectory`, содержит абсолютный путь к рабочей копии с именем пользователя macOS; это единственное вхождение `/Users/` в отслеживаемых файлах. `.gitignore` не исключает файлы окружения, ключи, сертификаты и логи, поэтому их можно случайно добавить командой `git add .`.
Ожидается: `context.workingDirectory` равно `"."` (путь относительно корня репозитория). `.gitignore` дополнительно игнорирует `.env`, `.env.*`, `*.key`, `*.pem`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `id_rsa`, `id_ed25519`, `id_ecdsa`, `*.log` в корне и во вложенных папках; `.env.example` остаётся доступным для добавления как шаблон без секретов.

Выбран краткий путь: меняются только конфигурация репозитория и документ; код приложения, сборка, подпись, идентичность приложения и его приватность (INV-3, INV-4) не затрагиваются.

## Ограничения

- Не меняется: код, `Package.swift`, `Resources/Info.plist`, Bundle ID, подпись, скрипты, настройки приложения, аппаратная логика; существующие правила `.gitignore`.
- `.gitignore` не действует на уже отслеживаемые файлы. На момент спецификации среди 95 отслеживаемых файлов нет файлов с перечисленными именами и расширениями; если найдутся, о них сообщается пользователю без вывода содержимого и без удаления из Git.
- Потребители `context.workingDirectory`: скрипты, хуки и код поле не читают; скилл `.agents/skills/sdd-init` только записывает его по шаблону. Абсолютный путь никому не нужен.
- Затронутые инварианты из `architecture.md`: нет.

## Проверки

| ID | Тип | Что запускается или проверяется |
|---|---|---|
| V-01 | автоматическая | `python3 -m json.tool docs/specs/knowledge-graph.json` и чтение `context.workingDirectory` |
| V-02 | автоматическая | `git grep -n "/Users/"` ничего не находит |
| V-03 | автоматическая | `git check-ignore -v --no-index` для имён в корне и в `Sources/x/` (без создания файлов) |
| V-04 | автоматическая | `git ls-files -ci --exclude-standard` пуст; `git ls-files -oi --exclude-standard` по исходным папкам пуст; сравнение прежних строк `.gitignore` |
| V-05 | автоматическая | `git diff --check`, `git status --short` |

Ручная проверка не нужна: поведение приложения не меняется. Сборка не запускается (правило «Только документация» в `docs/specs/README.md`, раздел «Выбор проверок»; код не меняется).

## Результат

- Изменения: `.gitignore` (новые блоки «Secrets and local environment» и «Logs» в конце файла), `docs/specs/knowledge-graph.json` (`context.workingDirectory` → `"."`, `metadata.updated`, `metadata.updatedBy`), этот файл, реестр в `docs/specs/README.md`. Коммит не создавался.
- AC-01: выполнено — JSON валиден, поле равно `"."` (V-01); `git grep "/Users/"` пуст (V-02).
- AC-02: выполнено — все 13 имён игнорируются в корне, `Sources/x/` и `docs/a/b/` (V-03, `git check-ignore -q --no-index`).
- AC-03: выполнено — `.env.example` в корне, `Sources/x/` и `docs/a/` не игнорируется (V-03, код выхода 1). `git check-ignore -v` печатает и отрицающее правило `!.env.example` с кодом 0, поэтому вывод без `-q` проверкой не считается.
- AC-04: выполнено — `git ls-files -ci --exclude-standard` пуст; среди неотслеживаемых файлов исходных папок игнорируется только `.claude/settings.local.json` прежним правилом строки 9; прежние 9 строк `.gitignore` побайтно совпадают (V-04).
- AC-05: выполнено — `git diff --check` без ошибок; `git status` показывает только `.gitignore`, `knowledge-graph.json` и `changes/0006-repo-secret-hygiene/` плюс реестр (V-05).
- Отслеживаемых файлов с секретами по перечисленным шаблонам не найдено.
- Не проверено: содержимое отслеживаемых файлов на секреты внутри обычных исходников и история Git не сканировались — вне объёма изменения. Ограничение: `.gitignore` не защищает от `git add -f` и не действует на файлы, уже добавленные в индекс.
