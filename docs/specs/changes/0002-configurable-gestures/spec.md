# CH-0002: Настраиваемые жесты и переключение рабочих столов

Статус: реализовано
Путь: полный
Дата: 2026-10-12
Документы: [план](plan.md) · [отчёт](report.md) · ADR: не требуется (см. план, «Влияние на архитектуру»)

## Проблема

Пользователь сообщает: жесты не работают, из всех направлений срабатывает только Mission Control; действия жестов нельзя выбрать, они зашиты в коде.

Что видно в коде (коммит `33c4732`):

1. `ActionExecutor.gesture(_:)` жёстко сопоставляет направления: влево/вправо — symbolic hotkey 79/81, вверх и нажатие — Mission Control, вниз — symbolic hotkey 33. Настроек направлений нет ни в `Preferences`, ни в UI.
2. Mission Control открывается через `NSWorkspace` (`openSystemApplication`), а остальные направления синтезируют сочетание клавиш через `ActionExecutor.symbolic(_:fallback:)`. Этот метод читает файл `com.apple.symbolichotkeys`. На Mac пользователя (macOS 27.0.1) у записей 79 и 81 есть только `enabled = true`, без `value`: сочетание по умолчанию в файле не записано. Поэтому код берёт запасной вариант `(123, .maskControl)` / `(124, .maskControl)`: ⌃← без флага Fn. Системное сочетание «Переместиться на один рабочий стол влево» по умолчанию — ⌃← с модификаторами `0x840000` (Control + Fn): стрелки всегда несут флаг Fn. Отправленное событие не совпадает с сочетанием, и рабочий стол не переключается.
3. События отправляются через `CGEventSource(.privateState)` в `.cghidEventTap`, тогда как `SpotlightShortcut`, введённый для macOS 27, читает действующее сочетание у WindowServer (`CGSGetSymbolicHotKeyValue`) и отправляет его через `.hidSystemState` в `.cgSessionEventTap`.

Не подтверждено: доходят ли Raw XY и распознаётся ли направление на мыши пользователя. Нажатие без движения тоже даёт Mission Control, поэтому по наблюдению «работает только Mission Control» нельзя отличить «направление не распознано» от «сочетание не сработало». Для этого добавляется показ последнего распознанного жеста (R-07).

## Цель

Жест каждого направления выполняет выбранное пользователем действие; переключение рабочих столов влево и вправо использует действующее системное сочетание macOS и доступно как обычное действие.

## Не входит в задачу

- Синтез системного свайпа Dock (DockSwipe), как в OpenLogi: приватный формат событий различается между версиями macOS (в OpenLogi отдельная ветка для macOS 27). Возможен отдельным изменением, если сочетания клавиш не сработают на мыши.
- Срабатывание жеста во время движения (до отпускания кнопки). Жест по-прежнему выполняется при отпускании.
- Разные действия жестов для профилей приложений: назначения направлений общие для всех профилей.
- Переход к рабочему столу по номеру, Mission Control через сочетание клавиш.
- Изменение команд HID++ и порядка захвата контролов.

## Текущий сценарий

1. Кнопке назначено «Жесты»; захват включает для неё Raw XY.
2. Пока кнопка нажата, `GestureAccumulator` суммирует смещения; при отпускании `direction` возвращает строку направления или `nil` (меньше 60 единиц).
3. `ActionExecutor.gesture(_:)` выполняет фиксированное действие; `nil` → Mission Control.
4. Влево/вправо/вниз — сочетания из файла настроек или запасные без Fn.

## Ожидаемый сценарий

1. Кнопке назначено «Жесты». В карточке кнопки появляется блок «Направления жеста» с пятью строками: вверх, вниз, влево, вправо, нажатие без движения. Для каждой строки выбирается действие.
2. По умолчанию: вверх — Mission Control, вниз — окна приложения, влево — рабочий стол слева, вправо — рабочий стол справа, нажатие — Mission Control (как раньше).
3. При отпускании кнопки направление определяется как раньше, выполняется выбранное для него действие, отправляется виброимпульс (кроме «Ничего»). На странице «Кнопки и жесты» показывается последний распознанный жест и выполненное действие.
4. «Рабочий стол слева» и «Рабочий стол справа» — обычные действия: их можно назначить любой кнопке, направлению жеста и позиции кольца.
5. Сочетания системных действий (рабочие столы, окна приложения, показать рабочий стол, Spotlight) читаются у WindowServer. Если сочетание отключено, оно временно включается на время доставки события и затем возвращается в прежнее состояние, как уже делается для Spotlight.

## Затронутые компоненты и контракты

- Компоненты: `MouseCore/Preferences.swift` (`MouseAction`, `GestureDirection`, `GestureActions`, `Preferences.gestures`, `GestureAccumulator`), `ActionExecutor`, `SpotlightShortcut` → `SymbolicShortcut`, `AppModel.handle(_:)`, `ButtonAssignmentsView`, `MainView.buttons`, `ArtworkPreview`.
- Контракты: формат `preferences.v1` — новый необязательный ключ `gestures`, новые значения `MouseAction` `previousDesktop`, `nextDesktop`. Тексты ошибок системных сочетаний обобщены. HID++, CLI-флаги, подпись не меняются.
- Инварианты: INV-1/INV-2 — проверки только на подставных зависимостях, назначенные действия агент не запускает; INV-3 — последний жест хранится только в памяти; INV-8 — `MouseCore` остаётся на `Foundation`; INV-14 — ручной `init(from:)` с `decodeIfPresent`; INV-5, INV-6, INV-12, INV-16 — захват не меняется.
- Анализ влияния: поток событий 4.2 меняет только выбор действия после отпускания; владение новым состоянием (`lastGesture`) — `AppModel` на main; `SymbolicShortcut` хранит состояние возврата на main, как прежде `SpotlightShortcut`.

## Совместимость, миграция и восстановление

- Сохранённые настройки: прежний JSON читается; ключ `gestures` отсутствует → значения по умолчанию. Ручной `init(from:)` у `Preferences` также перестаёт сбрасывать всё при отсутствии других неопциональных ключей (частично P-01).
- Откат на прежнюю версию: прежний декодер игнорирует `gestures`, но не знает значений `previousDesktop`/`nextDesktop`. Если они назначены кнопке или кольцу, прежняя версия сбросит настройки к значениям по умолчанию (поведение раздела 8 `architecture.md`). Принято как допустимое: откат не поддерживается.
- Аппаратное состояние: не меняется (R-08).
- Системные сочетания: файлы настроек не пишутся; временно включённое сочетание возвращается через 0,25 с или при выходе. При аварии процесса в этом окне помощник сочетание не возвращает: он восстанавливает только HID (U-11 в `architecture.md`). Пока окно открыто, такое же нажатие на клавиатуре тоже сработает как системное сочетание.
- Повреждённое или неизвестное значение одного направления заменяется значением по умолчанию и не сбрасывает остальные настройки (по итогам ревью, V-03).
