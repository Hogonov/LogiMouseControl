## Не проверено

Все [M-01…M-08](spec.md) **ждут проверки пользователем**: главное условие, знак, амплитуда, скорость, настройки natural scrolling, переходы lifecycle и поведение при уже открытом MC. Параметры 0,120 с, 0,008 с, 1,0 и знак являются начальными гипотезами. Реальные нажатия, прокрутка и действия агентом не запускались. При провале M-01/M-02 главный критерий не выполнен; ожидание завершения анимации не считается решением.

## Исправление P2 после независимого ревью — 2026-11-12

Первоначальный вывод V-07 об отсутствии замечаний уточнён независимым ревью: отмена зависела от допуска новых действий и Input Monitoring. Теперь у DockGestureController есть отдельный обязательный canSendTerminal, связанный с текущим AXIsProcessTrusted; AppModel использует тот же текущий AX для конечных горизонтальных кадров. Закрытие допуска новых команд не подавляет cancelled существующего жеста.

- CH-0007/R-09 → AC-09 → исправление в AppModel/DockGestureController → V-02/V-04: автоматическая часть выполнена; M-07 ждёт проверки пользователем по HARDWARE_VALIDATION.md.
- До изменения production-кода новая fake-проверка воспроизвела дефект: `AX permits terminal after admission closes: cancel`.
- После исправления ./scripts/test.sh прошёл: 38 проверок MouseCore, 13 SymbolicShortcut и DockGestureChecks. Дополнительно покрыты cancel/tick/отклонённый request при закрытом допуске и сохранённом AX, отсутствие поздних кадров и live-отзыв AX при устаревшем допуске.
- Debug build прошёл. Независимый read-only hid-reviewer проверил исправление: новых подтверждённых дефектов не найдено.
- Release .app пересобрана: scripts/build.sh прошёл, codesign --verify --strict подтвердил постоянную подпись Logi Mouse Control Local Signing. Приложение не запускалось.
- Production HID++, настройки, подпись приложения и системные настройки не менялись. Реальное действие Dock агентом не запускалось; аппаратный результат не подтверждён.

## Полный отказ MC и временное восстановление — 2026-11-12

Пользователь сообщил «вообще ничего» при вызове MC после завершения перехода. Причина полного отказа не установлена: изменение canSendTerminal не меняло обычный успешный request; параметры/временные метки и профильная отмена остаются гипотезами. Пользовательский результат не позволяет считать вертикальный backend рабочим.

- R-13 → T-10 → AC-14 → V-09/M-09: production gate отключает вертикальную подготовку до системных вызовов. Controller завершает собственное горизонтальное удержание и выполняет единственный legacy-вызов через ActionExecutor.
- Исправление разделения allowed/canSendTerminal сохранено. Горизонтальные свайпы не отключены.
- AC-14: автоматическая часть выполнена (V-09); физическое восстановление вызова не проверено, ждёт пользователя по M-09.
- V-09: ./scripts/test.sh прошёл (38 MouseCore, 13 SymbolicShortcut, DockGestureChecks), debug build прошёл. Read-only hid-review подтвердил сохранение горизонтального пути; найденная защита теста укреплена: production Prepared никогда не передаётся fake-controller, даже если gate регрессирует. 84 локальные ссылки, JSON и git diff --check прошли.
- scripts/build.sh прошёл; .app пересобрана, codesign --verify --strict подтвердил постоянную подпись Logi Mouse Control Local Signing. Приложение не запускалось.
- Первоначальные R-01/R-02 и AC-01/AC-02 не закрыты этим восстановлением. Без положительной пользовательской проверки вертикаль повторно не включать.
