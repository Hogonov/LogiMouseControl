# План CH-0001: Внедрение Spec-Driven Development

Спецификация: [spec.md](spec.md)
Статус: выполнен

## Выбранный подход

Развивать документы, созданные `sdd-init`, а не вводить параллельную систему:

- `docs/specs/architecture.md` переписывается по коду; заголовки, на которые ссылаются `.claude/rules/hid-safety.md` и `.claude/agents/hid-reviewer.md`, сохраняются. Инварианты получают идентификаторы INV-…, чтобы спецификации ссылались на них.
- `docs/specs/README.md` становится точкой входа: процесс, выбор пути, идентификаторы, проверки, реестр изменений и ADR.
- Изменения хранятся в `docs/specs/changes/NNNN-slug/`, решения — в `docs/specs/adr/NNNN-slug.md`, шаблоны — в `docs/specs/templates/`.
- Задачи живут в таблице плана, а не в отдельном файле: так меньше дублирования.
- Результаты краткого пути записываются в саму спецификацию, полного — в `report.md`.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Внешний инструмент SDD или установка дополнительных навыков | Запрос запрещает автоматическую установку навыков и лишние зависимости. |
| Отдельный каталог `specs/` в корне репозитория | Создал бы вторую систему рядом с `docs/specs/`. |
| Одна полная спецификация для любой правки | Избыточна для локальных исправлений; запрос требует соразмерных путей. |
| ADR на каждое изменение | Запрос прямо запрещает. |
| Отдельный файл `tasks.md` | Дублировал бы план; таблицы задач в плане достаточно для трассировки. |

## Влияние на архитектуру

| Вопрос | Ответ |
|---|---|
| Меняются границы модулей или зависимости? | Нет. |
| Меняются потоки данных, очереди или владение состоянием? | Нет, только их описание. |
| Меняется формат настроек, CLI или идентичность приложения? | Нет. |
| Затрагиваются инварианты INV-…? | Формулировки уточняются по коду, смысл прежних правил сохраняется; расхождения записываются отдельно. |
| Нужен ADR? | ADR-0001: структура документов и два пути. |

## Риски и откат

- Агенты `.claude/` ссылаются на заголовки `architecture.md` → заголовки сохраняются, V-06 проверяет их наличие.
- Документ снова разойдётся с кодом → правило в `AGENTS.md` обновлять архитектуру в том же изменении; раздел «Расхождения» показывает, как фиксировать найденное.
- Откат: `git revert` коммита; код не затронут.
