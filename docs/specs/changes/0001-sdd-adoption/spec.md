# CH-0001: Внедрение Spec-Driven Development

Статус: реализовано
Путь: полный
Дата: 2026-10-12
Документы: [план](plan.md) · [отчёт](report.md) · ADR: [ADR-0001](../../adr/0001-sdd-process-and-structure.md)

## Проблема

SDD в проекте инициализирован частично: скилл `sdd-init` (коммит `eb4a44a`) создал `architecture.md`, `ontology.md` и `knowledge-graph.json`, но:

- нет описанного процесса: когда писать спецификацию, где её хранить, как связывать требования с проверками;
- нет шаблонов спецификации, плана, отчёта и ADR;
- `architecture.md` не описывает потоки данных, владение состоянием, жизненный цикл, формат настроек и подпись; часть утверждений расходится с кодом (например, число SwiftPM targets в `Package.swift`);
- в `AGENTS.md` нет правил процесса, только запреты на проверку мыши.

## Цель

Требования фиксируются до реализации, архитектура описывает фактический код, а результат изменения проверяется по заранее записанным критериям. Поведение приложения не меняется.

## Не входит в задачу

- Изменение исходного кода, проверок, скриптов, `Package.swift`, `Resources/` и `.claude/`.
- Архитектурный рефакторинг и исправление найденных в коде проблем: они записываются как предложения.
- Новые продуктовые функции, в том числе для демонстрации процесса.
- Установка навыков и инструментов, сетевые сервисы и зависимости.
- Ретроспективные ADR для прошлых решений, причины которых не зафиксированы в источниках.

## Текущий сценарий

1. Агент получает задачу и сразу меняет код, опираясь на `AGENTS.md`, `CLAUDE.md` и `.claude/rules/`.
2. Ожидаемое поведение и критерии приёмки нигде не записываются до реализации.
3. Результат фиксируется в `docs/HARDWARE_VALIDATION.md` в свободной форме.

## Ожидаемый сценарий

1. Агент читает `docs/specs/README.md`, выбирает краткий или полный путь.
2. До реализации пишет спецификацию по шаблону: требования R-…, критерии AC-…, проверки V-… и M-….
3. Для полного пути пишет план с задачами T-…, связанными с требованиями, и при существенном решении ADR.
4. После реализации фиксирует результат каждого критерия и явно перечисляет непроверенное.
5. Обновляет архитектуру, словарь и граф знаний, если изменение их затрагивает.

## Затронутые компоненты и контракты

- Компоненты кода: не меняются.
- Документы: `AGENTS.md`, `CLAUDE.md`, `README.md`, `docs/HARDWARE_VALIDATION.md`, `docs/specs/*`.
- Контракты для агентов: заголовки `architecture.md`, на которые ссылаются `.claude/rules/hid-safety.md` и `.claude/agents/hid-reviewer.md`; пути документов, которые читает `.agents/skills/sdd-init/SKILL.md`.
- Инварианты: INV-1 и INV-2 (запрет проверок мыши) соблюдаются тем, что проверки ограничены документами.

## Совместимость, миграция и восстановление

Неприменимо к приложению: код, настройки и подпись не меняются. Откат — `git revert` коммита изменения.
