# ADR-0002: Плавное переключение рабочих столов через синтезированный DockSwipe

Статус: принято
Дата: 2026-10-12
Изменение: [CH-0003](../changes/0003-smooth-desktop-swipe/spec.md)

## Контекст

- Запрос пользователя от 2026-10-12: переключение рабочих столов жестом должно быть плавным, как свайп по трекпаду, без отдельного жеста на каждый стол.
- В CH-0002 рабочие столы переключаются symbolic hotkeys 79/81 (`SymbolicShortcut`). Это дискретное переключение: прогресс перехода нельзя связать с движением мыши.
- Публичного API для интерактивного перехода между рабочими столами нет. Трекпад передаёт Dock события DockSwipe (`kIOHIDEventTypeDockSwipe = 23`) с фазами и накопленным прогрессом.
- На macOS 27 Dock читает `IOHIDEvent`, вложенный в `CGEvent` типа 30, а приватные поля `CGEvent` игнорирует. Источники: Mac Mouse Fix `Helper/Core/Touch/TouchSimulator.m`, ревизия `f92d2d53a` (накопленный прогресс, правило ended/cancelled).
- На этом Mac (macOS 27) символы `IOHIDEventCreate`, `IOHIDEventSetIntegerValue`, `IOHIDEventSetFloatValue`, `IOHIDEventAppendEvent` (IOKit) и `SLEventSetIOHIDEvent` (SkyLight) находятся через `dlsym`; созданное ими событие имеет класс `HIDEvent` с ожидаемыми фазой, движением, вариантом и прогрессом. Проверка создавала событие только в памяти и ничего не отправляла.
- INV-16 перечисляет, что останавливается при паузе, сне, отключении и выходе; незавершённый жест Dock там не упомянут, потому что раньше его не было.

## Решение

- На macOS 27 и новее приложение отправляет события DockSwipe: `CGEvent` типа 30 с вложенным через `SLEventSetIOHIDEvent` событием `IOHIDEvent` (движение по горизонтали, вариант Dock primary, накопленный прогресс в рабочих столах, фаза в опциях; на ended и cancelled — дочернее событие скорости).
- Функции IOKit и SkyLight загружаются через `dlopen`/`dlsym`. Если хотя бы одной нет, на macOS ниже 27 или без Универсального доступа используется дискретное поведение CH-0002.
- Математика свайпа (порог, масштаб, сегменты, скорость, выбор ended/cancelled) живёт в `MouseCore` и проверяется без событий. Отправка — в отдельном классе `DockSwipe` приложения.
- INV-16 дополняется: пауза, сон, выход из сеанса, отключение мыши, перенастройка захвата и выход из приложения завершают начатый свайп фазой cancelled.
- Код Mac Mouse Fix не копируется; используются только факты о формате событий (указано в `THIRD_PARTY_NOTICES.md`).

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Оставить symbolic hotkeys и переключать стол во время удержания при каждом пройденном пороге | Только публичные события, проверенный путь | Каждое переключение — готовая анимация, рабочий стол не следует за мышью | Не выполняет запрос «как на трекпаде» |
| Приватные поля `CGEvent` (формат до macOS 27) | Без SkyLight | На macOS 27 Dock их игнорирует | У пользователя macOS 27 |
| Отправлять оба формата на всех версиях | Шире охват | Формат до 27 нельзя проверить на Mac пользователя; двойные события на 27 | Объём и риск без проверки |
| `HIDEvent` через Objective-C runtime | Прямая работа с классом события | Ручной вызов `alloc`/`init` через IMP в Swift рискован для ARC | C-функции IOKit создают тот же объект (`HIDEvent` — toll-free bridged `IOHIDEventRef`) |

## Последствия

- Становится проще: жест «влево/вправо» с рабочими столами ощущается как трекпад; несколько столов проходятся одним движением.
- Становится сложнее или дороже: зависимость от недокументированного формата Dock, который менялся в macOS 27; любой выпуск macOS может его сломать. Признак — рабочий стол не двигается во время удержания; откат — назначить другие действия либо прежняя версия.
- Что нужно поддерживать: INV-16; `DockSwipe` и проверки `SpaceSwipe`/`GestureSession`; U-13 и U-14 в `architecture.md`; пункты CH-0003 в `docs/HARDWARE_VALIDATION.md`.
