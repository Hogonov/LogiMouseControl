# Проверка MX Master 4

Это журнал по датам. Каждая запись фиксирует состояние на свою дату и не
переписывается; актуальное устройство приложения описано в
[docs/specs/architecture.md](specs/architecture.md). Например, первая запись
упоминает ad hoc-подпись: с коммита `2dcbc8b` `scripts/build.sh` подписывает
постоянным локальным сертификатом и отвергает ad hoc (расхождение D-10).

Новые пункты для проверки на мыши появляются из ручных проверок M-…
спецификаций в [docs/specs/changes/](specs/changes/) со ссылкой на изменение.
Отмечает пункт только пользователь, указывая дату.

## Подтверждено на этом Mac

- IORegistry видит MX Master 4: Logitech `046D:B042`, Bluetooth Low Energy.
- Debug и Release-сборки созданы; Release подписана ad hoc, codesign --verify --strict проходит.
- Приложение запускается; главное окно визуально проверено.
- Обнаружены одновременно работающие Mac Mouse Fix Helper, OpenLogi Agent и Overlay.
- До выдачи доступа IOKit возвращает отказ; перехват не включается.
- 18 проверок ядра выполняются локально без XCTest.
- Пользователь выдал разрешения предыдущей сборке; после изменения ad hoc подписи
  финальный процесс по-прежнему сообщает отсутствие разрешений. Доступ к HID
  не подтверждён, аппаратные записи не тестировались.

## Требует физической проверки после выдачи разрешений

- [ ] Список функций и кнопок считывается с мыши; заряд совпадает с устройством.
- [ ] Короткие движения колеса не теряются; медленный скролл плавный.
- [ ] Быстрый разворот прекращает предыдущий хвост движения.
- [ ] Свободное вращение работает в Safari, Chromium, Finder и редакторе кода.
- [ ] Боковое колесо: оба направления, независимая скорость.
- [ ] Трекпад сохраняет своё направление и поведение.
- [ ] DPI изменяется и перечитывается, затем восстанавливается исходное значение.
- [ ] SmartShift, ratchet, free-spin и порог подтверждаются устройством.
- [ ] Виброотклик ощущается физически, поддерживаются уровни интенсивности.
- [ ] Каждая кнопка срабатывает ровно один раз, системные кнопки не задерживаются.
- [ ] Кнопка жестов и тактильная панель различаются; начальный скачок панели игнорируется.
- [ ] Кольцо не перехватывает фокус целевого приложения; действия идут в него.
- [ ] Профиль автоматически выбирается и возвращается к общему.
- [ ] Пауза, выход, отзыв разрешений возвращают native HID.
- [ ] Сон, пробуждение, выключение мыши и переподключение не оставляют подвисших настроек.
- [ ] Force Quit активного приложения запускает аварийное восстановление.
- [ ] Easy-Switch отпускает захват перед переключением канала.
- [ ] Запуск при входе работает из постоянного пути установки.

Сборка и модульные проверки не подтверждают пункты физической проверки.

## Обновление изображений и системных действий — 21.09.2026

- Release-сборка проходит; 21 проверка ядра проходит, включая цвет из HID++,
  соответствие вариантов каталогу и преобразование координат точек кнопок.
- Все 14 ресурсов совпадают с SHA-256 каталога OpenLogi. Ресурсный bundle
  включён в `.app`; интерфейс отрисован из сборки отдельно от исходников.
- На этом Mac `AppleSymbolicHotKeys.64.enabled = false`: прежняя реализация
  Spotlight прекращала выполнение. Mission Control открывает системное
  приложение через NSWorkspace. Прямой запуск Spotlight.app пользователь
  проверил: на macOS 27 он возвращает ошибку запуска.
- Spotlight переведён на symbolic hotkey 64 через динамически загружаемый CGS.
  Отключённое сочетание временно включается, затем восстанавливается с задержкой
  для доставки событий. Файлы настроек не записываются. Логика проверяется
  только с подставными зависимостями, без реальных событий или открытия Spotlight.
- По правилу пользователя физические нажатия, прокрутку и запуск назначенных
  действий агент не проверяет. Пункты ниже выполняет пользователь.
- Инструмент просмотра работающего окна возвращает тайм-аут; диагностика
  новой сборки получает отказ macOS в доступе к HID (Мониторинг ввода).
  Цвет именно подключённого экземпляра и физические нажатия пока не подтверждены.

После запуска обновлённой сборки с разрешениями:

- [ ] Автоматически выбран белый корпус, диагностика сообщает `extendedModelID`.
- [ ] Нажатие каждой точки выбирает соответствующую кнопку; смена назначения
  сохраняется после перезапуска; недоступные контролы не появляются.
- [ ] Spotlight открывается и повторно вызывается при отключённом Cmd+Space.
- [ ] Mission Control вызывается физической кнопкой, жестом вверх и из кольца.
- [ ] Действия продолжают работать после переключения профиля и переподключения.

## Запуск приложений из кольца — 22.09.2026

- Debug-сборка и 22 проверки ядра проходят. Проверена совместимость со старым
  форматом настроек кольца и сохранение выбранного приложения.
- Приложение сначала ищется по bundle ID через NSWorkspace, а сохранённый путь

Ручная проверка пользователем:

- [ ] Для разных позиций кольца можно выбрать разные `.app`; названия сразу
  появляются в списке настроек и на кольце.
- [ ] Выбранные приложения запускаются и активируются из кольца по одному разу.
- [ ] Назначения сохраняются после перезапуска Logi Mouse Control.
- [ ] После перемещения приложения оно по-прежнему находится по bundle ID либо

## Настраиваемые жесты — 12.10.2026

Изменение [CH-0002](specs/changes/0002-configurable-gestures/spec.md).

- Причина, найденная в коде: на этом Mac у symbolic hotkeys 79/81 в
  `com.apple.symbolichotkeys` записано только `enabled = true`, без сочетания.
  Прежний код отправлял ⌃←/⌃→ без флага Fn, а системное сочетание по умолчанию
  его содержит (`0x840000`), поэтому рабочие столы не переключались.
- Теперь сочетание читается у WindowServer (`SymbolicShortcut`), как для Spotlight;
  действия направлений жеста настраиваются для каждой кнопки.
- 27 проверок ядра и 13 изолированных проверок сочетаний проходят, отладочная
  сборка и предпросмотр вёрстки сделаны. Жесты, переключение рабочих столов и
  запуск назначенных действий агент не проверял (INV-1).

Ручная проверка пользователем:

- [ ] M-01: при 2–3 рабочих столах жест влево открывает рабочий стол слева,
  вправо — справа.
- [ ] M-02: изменённое действие направления (например, «вверх → Spotlight»)
  выполняется вместо прежнего и сохраняется после перезапуска.
- [ ] M-03: после жеста строка «Последний жест» на странице «Кнопки и жесты»
  показывает направление. Если там всегда «нажатие», Raw XY не доходят — сообщить.
- [ ] M-04: «Рабочий стол справа» на боковой кнопке и в кольце работает; жест
  вниз открывает окна приложения; при отключённом в macOS сочетании действие
  срабатывает, а сочетание после этого снова отключено.
- [ ] Виброимпульс есть после жеста и отсутствует для направления «Ничего».

## Плавное переключение рабочих столов — 12.10.2026

Изменение [CH-0003](specs/changes/0003-smooth-desktop-swipe/spec.md),
[ADR-0002](specs/adr/0002-dock-swipe-synthesis.md).

- На macOS 27+ при назначении «влево/вправо» = «Рабочий стол слева/справа»
  горизонтальное движение с зажатой кнопкой жестов ведёт системный свайп
  рабочих столов (события DockSwipe), как трекпад. Один стол — около 800 единиц
  при 1000 DPI (≈2 см), доводка — с середины или быстрым движением.
- 32 проверки ядра и 13 изолированных проверок сочетаний проходят, отладочная
  сборка и предпросмотр вёрстки сделаны. События Dock агент не отправлял и
  жест не проверял (INV-1).

Ручная проверка пользователем:

- [ ] M-01: при 3+ рабочих столах удерживать кнопку жестов и медленно вести мышь
  вправо — рабочий стол сдвигается вслед за мышью; отпустить на середине —
  переход доводится или возвращается; влево — в обратную сторону. Если стол не
  двигается, а переключается только после отпускания, сообщить версию macOS.
- [ ] M-02: не отпуская кнопку, вести мышь дальше — проходятся несколько рабочих
  столов подряд, на каждом виброимпульс. Быстрый короткий рывок тоже переключает.
- [ ] M-03: переключить «Естественное прокручивание» — направление не меняется.
- [ ] M-04: нажатие без движения, жест вверх и вниз работают как прежде.
- [ ] M-05: во время начатого свайпа поставить паузу из меню — рабочий стол
  возвращается на место, ничего не «зависает».
- [ ] Расстояние на один стол удобное (если нет — сообщить: больше или меньше).
